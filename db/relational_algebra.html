關聯式代數 (Relational Algebra)

揭開 SQL 引擎背後的數學面紗：用代數運算子建構查詢樹。

一、 起｜生活化比喻 (概念引入)

🍔 速食店自動點餐機的底層邏輯：
當你按下一連串的點餐按鈕時，你心裡想的是「我要一份有起司的牛肉漢堡套餐」。這是一個宣告式的需求 (Declarative)。但對點餐機背後的廚房流程來說，它必須拆解成一套標準操作程序：「先從所有肉排中『篩選』出牛肉，再『切出』起司片，最後將肉排、起司和麵包『結合』在一起」。關聯式代數就是資料庫引擎的廚房操作程序，它將人類宣告式的 SQL 語句，轉譯成一步一步嚴格的數學運算子，指導機器如何實際把資料撈出來。

二、 承｜教科書級文字詳解 (Why, What, How)

首先，我們必須理解「為什麼 (Why)」在我們已經有了極度好用的 SQL 語言後，考研與學術界還要折磨學生去學那些像希臘符號一樣的關聯式代數？因為 SQL 是一種高階的「宣告式語言 (Declarative Language)」，它只告訴系統「我想要什麼結果」，卻沒有告訴系統「應該怎麼去抓這些資料」。資料庫底層的查詢最佳化器 (Query Optimizer)，無法直接看懂 SQL，它必須將 SQL 轉換成以代數運算子構成的「查詢樹 (Query Tree)」。藉由套用數學上的結合律與交換律，優化器能夠重新排列這些代數運算子，找出執行成本最低的撈取路徑，這是提昇資料庫效能的核心命脈。

接下來了解「是什麼 (What)」。關聯式代數是一套針對「關聯 (Relations，即表格)」操作的封閉型數學系統。所謂封閉性，是指任何一個運算子吃進一個或兩個表格後，吐出來的結果「絕對還是另一個表格」。這套系統分為兩大類運算子：一元運算子 (Unary Operators) 僅對單一表格進行操作，例如負責水平切出特定列的「選擇 (Select, σ)」，以及負責垂直切出特定欄位的「投影 (Project, π)」。另一類則是二元運算子 (Binary Operators)，負責將兩個表格組合在一起，包含了集合論中的聯集 (∪)、交集 (∩)、差集 (−)，以及極度重要的卡氏積 (×) 與連接 (&Join;)。

最後我們探討「如何運作 (How)」，特別是最難懂但最常用的「自然連接 (Natural Join, &Join;)」。當我們想要合併「學生表」與「修課表」時，如果我們直接使用卡氏積 (×)，會產生所有可能的神奇組合，包含學號 A 的人配上學號 B 的修課紀錄，這是毫無意義的。自然連接的運作機制是：系統會自動尋找這兩個表格中「欄位名稱完全相同」的屬性（例如都叫 學號），然後嚴格要求這兩個欄位的值必須相等，才會將這兩列資料合併，並且聰明地把重複出現的欄位名稱給剔除掉一個。這完美對應了我們在實務中串接 Primary Key 與 Foreign Key 的邏輯。

四、 合｜重點標示與提點

在撰寫解答時，千萬不要把 σ (Select) 和 SQL 裡面的 SELECT 搞混了！關聯式代數的 σ 是在做資料列的「條件過濾」，等同於 SQL 的 WHERE；而代數的 π (Project) 才是負責挑選欄位，等同於 SQL 的 SELECT。考場上最愛考的申論題就是給你一串囉唆的中文需求，要你寫出對應的代數式。請記住口訣：「由內而外寫，先做 Join 串接，再做 Select 篩選列，最後外層包上 Project 挑欄位。」

📝 互動式考古題 (Exam Practice)

🎯 [中央資管 109] 已知關聯 學生(學號, 姓名, 系級) 與 修課(學號, 課程名稱, 成績)。請以關聯式代數表達：「找出所有修習過『資料庫』課程，且成績大於 80 分的『學生姓名』與『系級』」。
【詳細解題推導過程】

Step 1: 確立所需的表格與關聯 (Join)
我們需要學生的「姓名與系級」(位於學生表)，以及過濾修課的「課程名稱與成績」(位於修課表)。
因為資訊散佈在兩張表，我們必須先將它們透過共有的屬性「學號」進行合併。
使用自然連接：(學生 &Join; 修課)

Step 2: 加入過濾條件 (Select, σ)
題目要求：「課程名稱為資料庫」且「成績大於 80 分」。
我們將這個條件套用在剛才合併出來的巨大關聯上：
σ 課程名稱='資料庫' ∧ 成績>80 (學生 &Join; 修課)

Step 3: 提取目標欄位 (Project, π)
過濾完畢後，這張表包含了學號、姓名、系級、課程名稱、成績等所有欄位。但題目只要顯示「學生姓名」與「系級」。
因此我們在最外層包上投影運算子：
π 姓名, 系級 ( σ 課程名稱='資料庫' ∧ 成績>80 (學生 &Join; 修課) )

【標準答案】
π 姓名, 系級 ( σ 課程名稱='資料庫' ∧ 成績>80 (學生 &Join; 修課) )
(註：若為了查詢優化最佳化，先對修課表做 Select 縮小資料量再做 Join 亦是極佳的寫法：π 姓名, 系級 ( 學生 &Join; (σ 課程名稱='資料庫' ∧ 成績>80 (修課)) ))
🎯 [成大資管 110] 關聯式代數中的「投影 (π)」運算子與 SQL 中的 `SELECT` 指令，在處理結果的「重複資料」時，有何根本性的學術差異？請說明原因。
【詳細解題推導過程】

1. 理論基礎的差異：
- 關聯式代數的投影 (π) 是嚴格建構在 集合論 (Set Theory) 之上的。在數學的集合定義中，集合內的元素必須是互異的（不可重複）。因此，當投影運算子挑出指定的欄位後，如果出現了完全相同的資料列，它在學術定義上會「自動強制消除」重複的 Tuple，確保結果仍是一個合法的數學集合 (Set)。
- SQL 的 `SELECT` 則是建構在實務上的 多重集 (Multiset / Bag Theory) 概念上。為了避免資料庫引擎每次都要花費巨大的運算資源去進行排序與去重檢查，SQL 的 `SELECT` 預設「不會」消除重複的列。

2. 結論與實務對應：
關聯式代數的 π A,B (R)，其實際對應的 SQL 語法並不是單純的 SELECT A, B FROM R，而是必須明確加上修飾詞的 SELECT DISTINCT A, B FROM R，才能完全符合代數上的語意與結果。

# 專案名稱：資管所考研知識庫 (IM Exam Knowledge Base) - V4 終極詳解旗艦版

## 1. 專案目的與核心精神
建立一個統整資管所考試科目（資料庫、資料結構與演算法、計算機概論、機器學習等）的個人專屬靜態網頁知識庫。
**核心精神**：拒絕空泛的重點條列！必須產出「教科書等級的萬字詳解」，並搭配「現代化高顏值介面」、「圖表輔助」與「互動式考古題」，打造能真正幫助零基礎跨考生考上台政的硬核複習系統。

## 2. 檔案與目錄結構規範
專案必須嚴格保持以下階層，新增頁面時需自動分類至對應資料夾：
/
├── index.html          # 首頁 (以卡片網格 Grid 排列所有知識點入口)
├── css/
│   └── style.css       # 全域共用樣式表
├── db/                 # 資料庫 (Database)
├── ds_algo/            # 資料結構與演算法 (Data Structures & Algorithms)
├── cs/                 # 計算機概論 (Computer Science)
└── ml/                 # 機器學習 (Machine Learning)

**命名規則**：檔案名稱一律使用「小寫英文 + 底線」（例：`db/relational_algebra.html`），絕不可使用中文檔名。

## 3. 網頁視覺與排版規範 (UI/UX)
- **排版要求**：導覽列與主標題之間的 `margin` 或 `padding` 不得超過 3rem，絕不可在頁面頂部留下大片空白。
- **視覺風格**：現代卡片式設計 (Card UI)、毛玻璃效果 (Glassmorphism)。
- **色彩與特效**：白底 (`#ffffff`) 或極淺灰底 (`#f8fafc`)，深灰字體 (`#333333`)，重點元素加入漸層藍紫色。按鈕與連結需有 `hover` 平滑過渡 (`transition: 0.3s`)，頁面載入需有淡入效果。
- **閱讀體驗**：字體排版需具備良好的行距 (`line-height: 1.6` 以上) 與段落間距，避免文字全擠在一起。

## 4. 內容生成深度規則 (硬核詳解 + 圖表輔助)
**【警告】絕對禁止只給條列式重點或大綱！** 當我要求新增知識點時，內容必須極度扎實，嚴格遵守以下「起承轉合」結構：

1. **起｜生活化比喻 (概念引入)**：第一段必須用一句日常場景解釋該抽象概念（如：將正規化比喻為整理衣櫃），降低學習門檻。
2. **承｜教科書級文字詳解 (核心血肉)**：
   - 必須用 3 到 5 個完整的段落，深入解釋該知識點的「Why (為什麼需要它)」、「What (定義與數學/邏輯原理)」、「How (如何運作)」。
   - 解釋演算法或機制時，必須一步一步推導，把讀者當作完全沒基礎的新手來教。
3. **轉｜視覺化強制要求 (圖解與表格)**：
   - **強制配圖 (Mermaid.js)**：只要遇到系統架構、演算法流程、樹狀圖或 ER Model，必須使用 `<div class="mermaid">` 區塊渲染結構圖。
   - **強制表格 (`<table>`)**：遇到概念對比（如 SQL vs NoSQL）、優缺點分析、步驟拆解或範例資料表時，必須使用 HTML 表格呈現。
4. **合｜重點標示與提點**：常考關鍵字必須使用粗體 `<strong>` 或 `<code>`，並加上淺色底色高亮。明確指出「這個概念在考場上最常怎麼考」。

## 5. 頁面 HTML 骨架結構 (AI 執行規則)
每個新增的 HTML 檔案必須包含完整區塊：
1. **CDN 引入**：`<head>` 需引入 `../css/style.css` 及 Mermaid.js 的 CDN。
2. **頂部導覽列 (Sticky Header)**：固定在頂部，包含「🏠 回首頁」按鈕。
3. **主標題區塊 (Hero Section)**：包含知識點大標題 (`<h1>`) 與一句話重點摘要。
4. **硬核詳解區 (Detailed Content)**：依序放入生活化比喻、**長篇幅的學術原理解釋**、圖解 (Mermaid) 與表格。
5. **互動式考古題 (Exam Practice)**：
   - 位於頁面最底部 `<section class="exam-section">`。
   - 自動附上 2~3 題「資管所經典考古題」。
   - 必須使用 HTML5 `<details>` 和 `<summary>` 製作隱藏式解答。解答內需包含**詳細的解題推導過程**，而非只給答案。

## 6. AI 自動化互動守則
當我下達「請幫我新增 [某知識點]」或「批量生成 X 個知識點」時：
1. 自動判斷所屬科目並建立檔案於對應資料夾。
2. **【最高指導原則】** 確保內容具備足夠的文字篇幅與知識密度，不要為了趕進度而偷工減料。
3. **強制更新首頁**：建立新頁面後，自動修改 `index.html`，將新連結以精美卡片樣式加入首頁網格清單。
4. 完成後，簡短回報路徑與更新狀態。

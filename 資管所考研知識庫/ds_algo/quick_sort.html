快速排序法 (Quick Sort)

Divide and Conquer 的極致！從 Pivot 選擇到 Partition 切割，徹底解析最常考的高效排序。

一、 起｜生活化比喻 (概念引入)

🏃 體育課的操場排隊：
體育老師要全班依身高排隊。他沒有叫大家互相比較，而是隨便在隊伍中抓了一個同學（假設叫小明）當作「基準 (Pivot)」。老師大喊：「比小明矮的，全部跑到小明左邊；比小明高的，全部跑到右邊！」一陣混亂後，小明左邊都是矮子，右邊都是高個，小明自己則永遠站在了全班最正確的位置上。接著，老師對左邊與右邊的群體重複同樣的動作，直到所有人都站定。這就是快速排序法 (Quick Sort) 神奇且高效的運作原理。

二、 承｜教科書級文字詳解 (Why, What, How)

在排序演算法的領域中，我們必須先問「為什麼 (Why)」實務界最愛用 Quick Sort？早期的氣泡排序 (Bubble Sort) 慢得令人髮指 (O(n²))，而同為 O(n log n) 的合併排序 (Merge Sort) 雖然效能穩定，但它需要額外配置與原始陣列一樣大的記憶體空間 (O(n)) 來暫存資料。Quick Sort 的偉大之處，在於它能在不需要大量額外記憶體的情況下（In-place 原地排序），運用極佳的快取區域性 (Cache Locality)，在平均情況下展現出輾壓群雄的實際執行速度。

接著剖析「是什麼 (What)」構成了 Quick Sort。它的核心思想是演算法四大策略中的 Divide and Conquer (各個擊破 / 分治法)。整個系統建立在兩個核心組件上：第一個是 Pivot (樞紐/基準值) 的挑選；第二個是 Partition (分割) 函數。Partition 的任務並不是立刻把資料排好，而是確保在執行完畢後，Pivot 左邊的元素通通比 Pivot 小，右邊的元素通通比 Pivot 大。這個動作保證了 Pivot 該回合結束後，絕對會落在最終排序完成時的正確 Index 上。

最後我們逐步推導「如何運作 (How)」。標準的 Partition 操作會設定兩個指標：i 從左邊往右找「比 Pivot 大」的元素，j 從右邊往左找「比 Pivot 小」的元素。當兩人都找到目標時，就將這兩個元素互換。這個找尋與互換的過程持續進行，直到 i 與 j 錯身交會，此時交會點就是 Pivot 該待的位置，我們將 Pivot 交換過去，就完成了一次分割。隨後，演算法透過「遞迴 (Recursion)」，分別將 Pivot 左半邊的子陣列與右半邊的子陣列再次送入 Quick Sort 中。當所有遞迴切割到只剩一個元素時，整條陣列就奇蹟般地排序完成了。

Quick Sort 演算法特性與複雜度總表

分析面向理論數值 / 狀態詳細推導與原因說明
最佳時間複雜度 O(n log n) 每次挑選到的 Pivot 都非常幸運地將陣列「完美對半切」。遞迴樹的深度為 log n，每一層的 Partition 需要掃描 n 個元素。
最差時間複雜度 O(n²) 當陣列已經排序好，且每次都傻傻選「第一個元素」當 Pivot 時。每次分割都會切出「長度為 0」與「長度為 n-1」的兩半，徹底喪失 Divide and Conquer 的優勢。
空間複雜度 O(log n) 雖然是 In-place 排序不需宣告新陣列，但遞迴呼叫 (Recursive Call) 會消耗系統的呼叫堆疊 (Call Stack)。平均深度為 O(log n)。
排序穩定性 (Stable) 不穩定 (Unstable) 在 Partition 過程中，為了將大元素與小元素遠距離對調，極容易破壞掉原本數值相同元素的相對順序。

四、 合｜重點標示與提點

在資管所的演算法考題中，Quick Sort 是不敗的經典。考官最喜歡問兩個陷阱題：第一是「什麼情況下 Quick Sort 最慢？」答案是陣列已經正向或反向排序，且挑選極值作為 Pivot，退化為 O(n²)。第二是「如何改良避免最差情況？」此時你必須寫出專有名詞 Median-of-three (三數取中法)，也就是同時看陣列的「頭、中、尾」三個元素，取數值排行中間的那一個當作 Pivot，這能極大機率避免切出極端的子陣列，是實務上最標準的防禦手段。

📝 互動式考古題 (Exam Practice)

🎯 [中山資管 110] 為什麼 Quick Sort 被稱為「不穩定排序 (Unstable Sort)」？請詳細解釋「穩定性」的定義，並舉一個具體的情境說明 Quick Sort 如何破壞穩定性。
【詳細解題推導過程】

1. 穩定排序 (Stable Sort) 的學術定義：
如果在未排序的原始陣列中，有兩個數值完全相同的元素 A 和 B，且 A 原本排在 B 的前面（即 Index(A) < Index(B)）。在經過排序演算法處理後，A 依然排在 B 的前面，我們就稱這個演算法具有「穩定性」。這在實務上對「多重鍵值排序」（例如先依據成績排序，成績相同再依據座號排序）至關重要。

2. Quick Sort 破壞穩定性的情境推導：
Quick Sort 的不穩定，來自於 Partition 步驟中「遠距離交換 (Swap)」的動作。
假設有一個陣列：[5, 8, 5*, 2, 9]。注意這裡有兩個 5，為了區別，我們將後面的標記為 5*。
- 我們選擇第一個元素 5 作為 Pivot。
- 指標 i 從左往右找比 5 大的，停在 8。
- 指標 j 從右往左找比 5 小的，停在 2。
- 此時 i 與 j 尚未交會，我們將 8 與 2 互換。陣列變為 [5, 2, 5*, 8, 9]。
- 接著 i 繼續往右，j 繼續往左，兩者錯身交會。
- 最後一步，我們必須將 Pivot 5 與 j 所在的 2 互換，讓 Pivot 歸位。
- 交換後陣列變為：[2, 5, 5*, 8, 9]。等等，請仔細看！

【結論】
雖然陣列看起來排序好了，但經過那次遠距離的 Pivot 交換，原本的 5 被丟到了 5* 的前面還是後面？
事實上，若發生遠距離交換，原本的 5 很可能被換到 5* 之後，破壞了他們原本先後出現的相對順序。因此，Quick Sort 是標準的 不穩定排序 (Unstable Sort)。
🎯 [台大資管 111] Quick Sort 與 Merge Sort 兩者在最佳、平均時間複雜度上皆為 O(n log n)，但在實務上多數標準函式庫 (如 C++ std::sort) 皆優先採用 Quick Sort 進行改良。請寫出 2 個詳細的系統底層原因。
【詳細解題推導過程】

實務上優先選擇 Quick Sort (通常是改良版的 Introsort) 的底層原因如下：

原因一：記憶體空間複雜度 (Space Complexity) 與 In-place 特性
Merge Sort 雖然效能穩定，但它的致命傷是「合併 (Merge)」階段無法在原陣列上直接操作。它必須配置與原資料等大 O(n) 的額外記憶體陣列來暫存合併結果，再搬回原陣列。若排序 10GB 的資料，就需要額外 10GB 的 RAM。而 Quick Sort 只要藉由指標互相交換即可完成，屬於 In-place Sort，額外空間僅需遞迴堆疊的 O(log n)，對系統負擔極小。

原因二：硬體快取區域性 (Cache Locality / Cache Hit Rate) 極佳
在現代計算機的記憶體階層架構中，CPU 讀取 Cache 的速度遠快於讀取 Main Memory。Quick Sort 的 Partition 過程是設置兩個指標，在一段連續的記憶體區塊中「依序、緊湊」地向中央推進並掃描資料。這種循序讀取的存取模式，極度符合 空間局部性 (Spatial Locality) 原理，使得 CPU 的 Cache Hit Rate 非常高，硬體加速效果卓越。相反地，Merge Sort 常在不同的記憶體區塊間跳躍搬移資料，Cache 命中率較差。這使得 Quick Sort 的「常數項 (Constant Factor)」非常小，實際執行速度通常是 Merge Sort 的 2 到 3 倍快。

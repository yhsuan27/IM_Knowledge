OSI 網路七層架構 (OSI 7-Layer Model)

網路通訊的聖經！以最生活化的物流比喻，逐層拆解資料封裝與通訊協定。

一、 起｜生活化比喻 (概念引入)

📦 跨國網購退貨的史詩物流：
想像你買了一台美國的機器，壞了要退貨。
第七層(應用層)：你寫了一封抱怨信。
第六層(表達層)：你把信翻譯成英文，並用膠帶密封。
第五層(會議層)：你打電話給對方確認他們準備好收貨了。
第四層(傳輸層)：你給包裹貼上追蹤碼，確保包裹要是寄丟了對方會通知你重寄。
第三層(網路層)：郵局決定包裹要搭哪班飛機飛過太平洋，並寫上雙方國家的地址(IP)。
第二層(資料連結層)：在台灣境內，包裹被交給大榮貨運，蓋上內部轉運站的條碼(MAC)。
第一層(實體層)：包裹被丟進貨車，輪胎在柏油路上摩擦，化為真實的物理移動。這就是 OSI 七層架構的封裝過程！

二、 承｜教科書級文字詳解 (Why, What, How)

在電腦網路發展的初期，我們面臨一個巨大的「為什麼 (Why)」需要標準架構的問題。1970年代，IBM 有自己的 SNA 網路，Apple 有 AppleTalk，不同廠商的電腦彼此之間語言不通、線材不相容，就像一個只說法語的村莊無法與只說日語的村莊交易一樣。為了解決這個通訊壁壘，國際標準化組織 (ISO) 在 1984 年發布了開放式系統互聯參考模型 (Open Systems Interconnection model, 簡稱 OSI)。它的終極目標是「模組化」，讓複雜的網路通訊被拆解成七個獨立的黑盒子，只要各廠商遵守每一層與上下層之間的標準介面，不管是哪家廠商製造的硬體或軟體，都能在全球網路上暢通無阻。

接下來我們剖析這七個黑盒子「是什麼 (What)」。OSI 將網路分為三大模組。最上面的 Layer 5 ~ 7 (應用層、表達層、會議層) 屬於「主機層次」，它們只存在於發送端與接收端的電腦系統內部，處理的是與人類使用者直接互動的應用軟體、資料格式轉換、加密解密，以及應用程式間對話的建立與同步。中間的核心 Layer 4 (傳輸層) 負責「端對端 (End-to-End)」的可靠度控制與流量控制，確保不管底層網路多麼殘破，資料都能完整無缺地交到對的應用程式(Port)手上。最底下的 Layer 1 ~ 3 (實體層、資料連結層、網路層) 則是真正的「媒體層次」，負責把資料化為封包，決定它該走哪條路徑穿越茫茫網海，最後轉換成光訊號或電訊號在實體銅線與光纖中狂奔。

最精華的考點在於資料「如何傳遞 (How)」，這個過程被稱為 封裝 (Encapsulation) 與 解封裝 (Decapsulation)。當你在瀏覽器按下 Enter 鍵，資料會從第七層開始，像包洋蔥一樣，每往下經過一層，該層的協定就會在資料的最前面加上一個專屬的「標頭 (Header)」，以此來指示接收端的同一層該做什麼事。這個被包裝過的資料區塊，在學術上有個統一名稱叫做「協定資料單元 (PDU)」。在傳輸層，PDU 被稱為 Segment (區段)；到了網路層加上 IP 標頭後，被稱為 Packet (封包)；到了資料連結層加上 MAC 標頭與尾端檢查碼後，變成 Frame (訊框)；最後在實體層化為 0 與 1 的 Bit (位元)。當這個 Bit 流到達接收端後，會由下往上，一層層把洋蔥剝開驗證，最後還原出純粹的資料交給使用者的應用程式。

四、 合｜重點標示與提點

在研究所的網路概論考卷中，OSI 永遠是配分最重的一環。你必須能夠秒答硬體設備所屬的層級：集線器 (Hub) 屬於 L1，因為它只會無腦放大物理訊號廣播；交換器 (Switch) 屬於 L2，因為它看得懂 MAC 位址，能進行智慧型轉發；路由器 (Router) 屬於 L3，因為它負責解析 IP 進行跨網段的路由導航。此外，第四層 (L4) 的 TCP (高可靠度、有連線) 與 UDP (低延遲、無連線) 的比較，以及它們使用 Port 號碼來辨識應用程式的機制，也是每年必考的經典申論題。

📝 互動式考古題 (Exam Practice)

🎯 [台大資管 108] 請問 Router (路由器) 與 Switch (交換器) 在 OSI 模型中分別運作在哪一層？它們的核心運作原理與處理的位址類型有何不同？請詳細推導。
【詳細解題推導過程】

1. Switch (交換器) 的運作機制：
- 所屬階層：Layer 2 資料連結層 (Data Link Layer)。
- 位址與 PDU： 處理的資料單元為 Frame (訊框)，依賴的位址是寫死在網卡硬體上的 MAC Address (實體位址)。
- 核心運作推導： Switch 的責任範圍僅限於「同一個區域網路 (LAN)」內部。當它收到一個 Frame 時，它會拆開 L2 的標頭，讀取「目的 MAC 位址」。接著它去查閱自己內部維護的 MAC Table（記錄哪個 MAC 連在哪個實體 Port 上），然後精準地將資料轉發到該特定 Port。它不關心資料要送往哪個國家，只關心這個房間裡誰是誰。因此，Switch 無法實現跨網段的通訊。

2. Router (路由器) 的運作機制：
- 所屬階層：Layer 3 網路層 (Network Layer)。
- 位址與 PDU： 處理的資料單元為 Packet (封包)，依賴的位址是軟體配置的 IP Address (邏輯位址)。
- 核心運作推導： Router 的使命是「連接不同的網路」。當資料需要跨越網段（例如從家裡送到 Google 伺服器），Switch 無能為力，只能把資料丟給 Default Gateway (通常就是 Router)。Router 收到 Frame 後，會剝掉 L2 標頭，露出 L3 的 IP 標頭，讀取「目的 IP 位址」。接著，它運用各種複雜的路由演算法 (如 OSPF, BGP) 查閱 Routing Table，決定這個封包下一步該往哪個介面送。決定後，Router 會重新為封包封裝上新的 L2 MAC 標頭，送往下一站。
🎯 [政大資管 110] 當我們談論傳輸層 (Transport Layer) 的通訊協定時，最常比較的就是 TCP 與 UDP。請從「連線機制」、「可靠度」與「適用情境」三個面向，詳細推導兩者的差異。
【詳細解題推導過程】

傳輸層 (Layer 4) 負責端對端的程序通訊，TCP 與 UDP 選擇了截然不同的設計哲學：

1. 連線機制 (Connection-oriented vs Connectionless)：
- TCP (傳輸控制協定)：是「連線導向」的。在正式傳輸任何資料前，雙方必須先進行嚴格的 Three-way Handshake (三方交握)（SYN → SYN-ACK → ACK）來建立虛擬連線通道，確認彼此都在線且準備好。結束時也需要四次揮手來優雅地中斷連線。這帶來了極高的建立成本。
- UDP (使用者資料段協定)：是「非連線導向」的。它不管對方在不在線上、塞不塞車，有資料就直接朝目標 Port 射過去，不進行任何事前溝通。

2. 可靠度與控制機制 (Reliability & Control)：
- TCP：提供絕對的「可靠傳輸」。它實作了 Sequence Number (序號) 來確保資料到達的順序不亂；實作了 ACK (確認回條) 與 Retransmission (逾時重傳) 來保證資料不遺失；還具備 Sliding Window (滑動視窗) 來進行流量與壅塞控制，避免把對方或網路塞爆。
- UDP：被稱為「盡力而為 (Best-effort)」的協定。它沒有序號、沒有確認回條、沒有重傳機制、更沒有流量控制。資料遺失了就遺失了，順序錯了也就錯了，完全交由上層應用程式自己想辦法。

3. 適用情境推導：
- TCP 的適用情境：因為具備保證送達的特性，適用於「一點資料都不能錯」的應用。例如：網頁瀏覽 (HTTP/HTTPS)、檔案傳輸 (FTP)、電子郵件 (SMTP)。少了一個字元網頁可能就亂碼了。
- UDP 的適用情境：因為沒有重傳與交握的延遲負擔，速度極快，適用於「講求即時性，且能容忍少量遺失」的應用。例如：即時視訊會議 (掉幀沒關係，但不能延遲 3 秒才說話)、線上直播、網路遊戲即時同步、以及 DNS 查詢（因為請求很小，重查一次比建立 TCP 連線還快）。
